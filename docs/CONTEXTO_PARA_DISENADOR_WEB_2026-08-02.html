Documento específico de incorporación

Cómo está hecha esta web y qué necesitamos rediseñar

Contexto concreto de Rutas B para intervenir la página existente con criterio gráfico y UX, sin necesidad de conocer herramientas de generación automática ni tocar datos sensibles.

Esta página ya funciona y recibe reservas. El encargo no es imaginar una web abstracta: es darle una identidad de autor coherente a este producto concreto, mejorar su experiencia móvil y ordenar todas sus pantallas bajo un mismo sistema.

La IA ha actuado como implementador técnico. No necesitas escribir prompts, aprender Astro ni entrar a la base de datos. Tu aporte es diagnóstico, arquitectura de información, sistema visual, componentes, prototipo, especificaciones y control de calidad sobre la web real.

01 · El producto que recibes

No partimos de cero

Ya existe un producto

La web está publicada, tiene reservas reales, versión inglesa y panel administrativo.

Hay una base visual

Logo, paleta editorial, tipografía, fotografías y componentes iniciales.

Hay restricciones reales

Datos, horarios, correos, permisos, despliegue y compatibilidad móvil.

Hay espacio de autoría

La interfaz funciona, pero necesita coherencia, carácter, jerarquía y una UX más deliberada.

03 · Flujo recomendado

De una decisión de diseño a la web

2. Diseño o especificación

Una modificación no se considera terminada porque “se ve bien” en una captura. Debe funcionar con contenido real, en castellano e inglés, con estados vacíos, errores, carga y tamaños de pantalla distintos.

04 · Cómo entregar decisiones

No hace falta hablarle a la IA

Puedes trabajar en Figma, PDF, una guía visual, capturas anotadas o especificaciones. Lo importante es evitar instrucciones ambiguas como “hazlo más moderno”.

Formato mínimo útil para cada cambio Pantalla o componente: Problema observado: Objetivo para el usuario: Cambio propuesto: Medidas, tipografía, color y espaciado: Comportamiento en móvil: Estados necesarios: Qué debe conservarse:

Si se entrega Figma, conviene usar Auto Layout, componentes, estilos definidos y nombres comprensibles. Si se entrega una captura, debe incluir medidas o referencias suficientes para no adivinar.

05 · Qué puedes tocar

Libertad visual con límites claros

Sí: diseñar libremente

  • Composición y jerarquía.
  • Sistema tipográfico.
  • Paleta y contraste.
  • Botones, tarjetas y formularios.
  • Menú móvil y navegación.
  • Uso de fotografía y logo.
  • Estados de interfaz.
  • Ritmo, espaciado y responsive.

No: cambiar sin coordinación

  • Slugs y códigos internos.
  • Campos o valores del formulario.
  • Reglas de aforo y disponibilidad.
  • Estructura de la base de datos.
  • Autenticación y permisos.
  • Claves o variables de entorno.
  • Reservas existentes.
  • Flujo de publicación y correos.

07 · Criterio de calidad

Qué revisaremos juntos

  • ¿Se reconoce una identidad propia y consistente?
  • ¿Se entiende qué se ofrece y cómo reservar?
  • ¿La ruta principal se presenta con suficiente deseo y confianza?
  • ¿El celular tiene la misma calidad que el escritorio?
  • ¿ES y EN conservan jerarquía, tipografía y composición?
  • ¿Los estados de error, carga, vacío, borrador y publicado son comprensibles?
  • ¿Se puede operar la web sin asistencia técnica cotidiana?
Prioridad de pantalla: Android vertical → PC → tablet horizontal → celular horizontal.
08 · Primer encargo

Qué necesitamos ahora

Una dirección visual única y aplicable a cinco plantillas: portada, catálogo, ficha de ruta, reserva/confirmación y página informativa. No buscamos rediseñar veinte páginas por separado.

  1. Auditar la web actual en celular y PC.
  2. Definir qué conservar y qué corregir.
  3. Proponer sistema visual y componentes comunes.
  4. Resolver primero portada, ficha de Sagrada Família y reserva móvil.
  5. Entregar decisiones suficientemente precisas para implementarlas.
